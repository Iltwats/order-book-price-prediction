# Improving the Connectome model

The next development cycle should improve the supplied GRU before replacing it. The most promising first experiment is a prediction head trained with an objective closer to the competition score. It preserves the recurrent weights and can preserve the current inference cost. The next experiments should add explicit causal feature changes and carefully fine-tune the upper GRU layer. External pretrained weights deserve two bounded transfer experiments, not a broad replacement campaign.

The strongest small Hugging Face candidate identified is IBM's **Granite PatchTSMixer**, whose published checkpoint is trained on electricity-transformer measurements. **Chronos-2-Synth** is the strongest documented synthetic-only candidate for an offline teacher. Neither has demonstrated a Connectome score improvement. Many otherwise attractive checkpoints have external market data in their training mixture, incomplete provenance, a forecasting interface that assumes historical targets, or an impractical streaming cost.[^1][^2][^3]

## Current evidence and remaining opportunity

The production model is still the supplied `112 → GRU128 → GRU128 → linear2` network. All 192,000 recurrent parameters are unchanged. Six learned affine coefficients and output scales were folded into the existing head; the deployed model contains 192,258 parameters. It processes every input row, clears state between sequences, and uses the validated ONNX Runtime implementation.[^4]

| Development control | Exact development WP | Interpretation |
| --- | ---: | --- |
| Original supplied model | 0.586188044 | Historical reference |
| Original model, outputs multiplied by 0.25 | 0.628562389 | Strong calibration control |
| Affine head fitted on 256 training sequences | 0.629237395 | Small learned correction |
| Current affine head fitted on 1,024 sequences | **0.629255535** | Incumbent to beat |

Approximately **98.39% of the development improvement over the original model is already achieved by the quarter-scale control**. This is a descriptive decomposition of these specific results, not a claim that calibration explains all predictive information. The learned affine transformation adds 0.000693146 WP over that stronger control; its paired development interval is [0.000469399, 0.000946672]. Increasing the affine training set from 256 to 1,024 sequences added only 0.000018140, with an interval crossing zero. Simply feeding more data into the same affine solver is therefore a low-cost control, not the principal model-improvement hypothesis.[^4]

The original confirmation comparison favored the current release: 0.640997995 versus 0.599669876, a difference of 0.041328119. Its interval and sequence-level records remain historical evidence. All 1,873 validation sequences have now been inspected through development or confirmation. A new manifest cannot restore their independence. Confirmation must not become a tuning target or be described as a new independent test. Future candidates must be compared with the **current calibrated release**, rather than repeatedly claiming improvement over the much weaker uncalibrated baseline.[^4][^5]

The current model delivers 38,291 callbacks/second against 34,962 for the actual original baseline on the measured Linux ARM64 host. Streamed loading, inference and scoring reach 36,249 rows/second, with approximately 370 MB peak RSS. The submission ZIP is 722,475 bytes. Model size is not our present bottleneck; preserving low per-row latency is more restrictive. The existing speed gate leaves only approximately **2.49 microseconds of additional callback time** relative to the original baseline on this host. Extra MACs, Python calls, state copies and ONNX operators all consume that allowance.[^6]

## Eligibility and task compatibility

The current competition rule requires public pretrained models to **“not contain external market data.”** Public availability or a permissive software license alone does not satisfy that condition. A checkpoint trained on another financial competition, Bitcoin, exchange rates or stock observations is not a clean replacement. An offline teacher carries the same provenance issue; distilling its outputs does not erase its training history. Where a corpus is only described as a subset of a broader collection, eligibility remains unresolved.[^1]

The live FAQ permits using the supplied training and validation files. That is an eligibility permission, not a guarantee of valid model selection. The next cycle should continue fitting learned components on the training file and reserve development for comparisons. No outside observations are needed for the recommended first experiments.[^1]

There is also a fundamental interface mismatch. Many time-series foundation models forecast future values of a target whose past values they observe. Our callback never receives `t0` or `t1`, even their historical values. It receives 112 anonymized features; both targets are undisclosed indicators of future movement of instrument i0. Feeding true previous targets into an offline teacher during training or validation would create information unavailable in deployment. A usable transfer model must instead learn a supervised mapping from **trailing feature history to the two labels**.[^7]

Feature semantics constrain architecture transfer. The columns distinguish instrument and price-like, volume-like and trade groups, but an index is a stable identifier rather than ordered book depth. `p0` is not a documented best bid. Standard physical spread, microprice and order-flow formulas are therefore not automatically meaningful. Same-column changes, lagged deviations, and learned interactions between documented groups are defensible experiments; assuming conventional LOB level adjacency is not.[^7]

### Two external-weight experiments worth preserving

**PatchTSMixer transfer versus random initialization.** Its documented ETTh1 data describes transformer electrical loads and oil temperature, rather than traded electricity prices. Its 512-step context, seven channels and 96-step forecasting head do not match our event stream. Retain an appropriate shared backbone only after verifying tensor compatibility, learn channel aggregation and a two-output head on competition data, and compare against the identical architecture with random initialization. A community ONNX conversion is useful export evidence, not proof that the adapted graph will run at our target latency.[^2][^8]

Use genuine trailing windows. At the first required prediction only 100 rows have been observed. A 512-row model needs an explicitly trained shorter-context adapter or the incumbent's predictions until adequate context exists. That early-context behavior must be identical in training, evaluation and submission. Do not silently insert historical labels or pretend zero padding preserves the checkpoint's original operating conditions. Stop if pretrained initialization fails to improve on both the random-initialization control and the incumbent under the chosen comparison protocol.

**Chronos-2-Synth as an offline feature encoder.** Its card explicitly states synthetic-only univariate and multivariate pretraining, providing much clearer provenance than mixed real-data foundations. Initially expose only 8–16 channels chosen using training data and trailing 128-row windows. A verified feature-extraction adapter and supervised head are required; the standard forecasting call does not directly predict our anonymous targets. Compare its representations with raw-window and original-GRU-state readouts using the same labels and training budget.[^3]

Only if that adapted teacher adds useful development signal should its predictions train a compact student. Generate teacher features and labels in bounded buffers, fit stacking or distillation decisions without using confirmation, and ship only the student. Synthetic-only provenance makes the experiment worth considering; it does not establish that the model will be accurate or affordable to adapt on the available CPU.

## First priority: a better objective for the existing head

The current fitting procedure uses sequence-normalized weighted MSE. It respects the target weights, but it is not the competition's clipped, per-sequence Pearson objective. Correlation ignores certain scale and offset changes until clipping intervenes. The large calibration gain and the unsuccessful larger MSE-head pilots justify testing objective alignment before concluding that the frozen representation is exhausted.[^4][^7]

Start from the **selected folded head**, retaining identity as a complete control. Compare the existing affine/ridge procedure with a linear correction trained on an equal-sequence weighted-correlation surrogate plus a small stabilizing MSE and parameter-anchor term. Regularize toward the current head, not toward an all-zero predictor. Apply the official clipped metric for every selection decision. The correlation objective's variance denominators need explicit safeguards for degenerate sequences; the training file lacks `is_scored`, so training must use eligible post-warm-up rows rather than inventing the hidden scoring mask. Research on correlation-oriented regression supports this objective family, while supplying no guarantee for this dataset.[^14]

There is a practical CPU/memory opportunity. For a linear head `p = Hβ + a`, each sequence and target can be summarized by target-weighted, centered hidden-state covariance `C`, hidden/target cross-covariance `v`, and target variance `s²`. With consistently normalized weights, the **unclipped-prediction** correlation is:

\[
\rho(\beta) = \frac{\beta^T v}{\sqrt{(\beta^T C\beta)s^2}}.
\]

The intercept disappears from this expression. Two 128-by-128 FP64 covariance matrices per training sequence require approximately **2.78 GB** across all 10,607 sequences, plus small moment vectors and metadata. Storing every final-layer state instead would require approximately **108.6 GB**, or **217 GB** for both layers. A bounded extraction pass through the unchanged ONNX encoder can therefore support repeated inexpensive readout optimization. Covariance construction itself costs O(rows × width²) and must be timed; the existing affine fit's speed cannot predict it. A synthetic numerical check reproduced direct row-wise correlation to 4.51e-17 absolute error.[^9]

This shortcut is not exact for the official score: clipping predictions depends on individual rows. Keep that distinction explicit. Freeze or separately calibrate the intercept, evaluate clipping and saturation on development, and compare with a bounded-row exact-clipped objective only if the moment-based surrogate is promising. If the selected head remains linear in the final hidden state, fold it into the existing ONNX tensors with no additional inference operators. Both-state or nonlinear corrections require new graph validation.

## Second priority: introduce observable causal dynamics

The literature on order-flow learning suggests testing changes and locally stationary inputs, while comparative LOB studies show that compact MLPs can be competitive with more elaborate networks. These findings motivate local experiments; their datasets and classification metrics do not predict our WP gain.[^10][^11]

A conservative branch preserves the incumbent GRU and adds a zero-initialized residual head over current features, same-column differences and deviations from a causal moving average. One proposed `336 → 32 → 2` MLP adds approximately 10,816 MACs and 44 KB of FP32 weights. That is about 5.7% of the GRU's matrix arithmetic, but does not guarantee a 5.7% latency increase: small ONNX operations and state management may dominate. Fit with both the established MSE control and the promising objective from the first experiment. Keep the incumbent's original preprocessing unchanged.[^12]

Restrict the initial search to a few feature families: same-column one-step differences; deviations from EMA8; and learned interactions between i0, i1 and the eight additional features. Initialize state from observed first rows, reset it between sequences, and express decay in event rows rather than seconds because timestamps are not supplied. Select normalization constants using training data only. Do not repeat the already unsuccessful output-EMA sweep without a distinct hypothesis.

## Third priority: carefully unlock recurrent fine-tuning

The trainable reconstruction has the correct documented gate ordering and bias structure, but currently fails the original strict long-sequence tolerance. That failure remains recorded. The diagnostics show much smaller discrepancies when both implementations receive the same previous hidden state, which is consistent with FP32 kernel differences amplified through recurrence. It does not justify declaring a strict pass.[^13]

A useful next check is a **zero-update roundtrip into the original ONNX graph**: recover weights, make no optimizer update, write them back into the original tensor layout, and require identical arrays plus bitwise original-ORT predictions and hidden states. Separately validate the trainable equations and gradients on tiny controlled cases. Preserve the original strict conversion check; if an approximate training path is used, predeclare and justify its acceptance criteria before inspecting newly trained results. A score-changing model is not expected to reproduce the original predictions, but its own training/export implementations still require a documented numerical audit.

Start recurrent training from the selected affine-folded model. First unfreeze only the upper GRU and head, then consider both layers. Penalizing deviation from pretrained weights is a different experiment from AdamW weight decay toward zero; the former directly preserves the useful starting representation. L2-SP and adaptive TBPTT research motivate these controlled choices but do not establish a Connectome improvement. Use an unchanged selected ONNX model as the teacher reference so teacher matching does not silently inherit a different reconstruction. Sequence boundaries, 99 warm-up rows, detached chunk states and whole-sequence loss normalization remain essential.[^13][^15]

Begin with one epoch on 256 training sequences, two small learning rates and one anchoring choice; time a small representative pilot before estimating larger jobs. Extend only a winning configuration to more data and a second seed. A 256-row backpropagation chunk retains recurrent forward context but limits gradient credit assignment; test 512 or 1,024 only after establishing a useful smaller experiment. Full training-set neural jobs have not been benchmarked and should not be promised a completion time from a one-sequence smoke test.

## Compact challengers and distillation

There are defensible architecture alternatives if the incumbent's representation proves limiting: a small GRU student, a cached causal depthwise TCN, and a small bilinear or diagonal-state model. A temporal model over stable feature identities is preferable to spatial convolutions that assume ordered book depth. Cache per-layer past activations; reevaluating a full window at every row defeats the proposed low-cost design.[^12]

Student widths 96 and 64 are already supported by offline training tools, but a smaller student does not automatically improve score. Its role is to retain an improved teacher's predictions while restoring runtime margin, or to provide a complementary cheap signal. The current unpromoted C++ kernel is not a prerequisite: architecture candidates should first use an explicitly supported ONNX adapter and the same complete-callback measurements.

An ensemble should be evaluated for incremental signal after calibration, not for model count. Fold multiple linear heads sharing the same frozen recurrence into one head where algebra permits; clipping individual heads before blending generally prevents that identity. Distinct recurrent teachers require separate states and compute. Fit mixing weights from sequence-disjoint training-fold predictions of the newly fitted components, measure paired development improvement, then distill if multiple backbones violate the speed gate. The supplied encoder's original training lineage is not known well enough to call it globally out-of-fold. Removing the teacher from the ZIP solves deployment cost, not provenance or student-generalization risk.

## Evidence standard for the next cycle

Freeze one capped experiment registry for the ten approaches while preserving the completed release and confirmation ledger. Repeated validation selection can overfit a holdout even when individual models appear well behaved; a bootstrap interval does not correct an adaptive search automatically.[^5] Use the existing 32/256/1,400 development hierarchy for correctness, screening and final local comparison, with nested folds and predeclared search limits where helpful. These folds improve discipline but do not make already inspected data pristine. Training-derived holdouts are untouched only by the newly fitted components; the supplied model may already have seen their labels during pretraining.

The existing one-shot confirmation function specifically compares against the original raw baseline. It must not be reused unchanged for round two or unlocked by deleting its receipt. A separate, explicit incumbent-relative development workflow is required; its comparator is the selected calibrated artifact and its provenance hash.

Require a positive paired mean difference against the incumbent, report both targets and sequence distributions, and repeat a stochastic winner with a second training seed. For a deterministic solver, use a predeclared training-subset or regularization-stability check; identical arithmetic rerun is not an independent replicate. Report 10,000-resample sequence-bootstrap intervals as descriptive uncertainty with their independence and selection limitations. Keep the old confirmation sealed during tuning. Any future reuse needs an explicitly recorded protocol and must be labelled reuse; fresh platform/private data remains the strongest independent check.[^16]

Before replacing the release, verify every-row updates, warm-up, resets, causality, finite outputs, owned return buffers, deterministic export, and full-sequence state behavior. Run three unprofiled Linux one-CPU callback repetitions and a streamed evaluation. Retain the current requirement that a score-changing model be no slower than the original baseline unless reliable judge timing establishes additional headroom. Measure the extracted offline ZIP rather than assuming checkpoint bytes equal package bytes.[^6]

No researched external model has been trained or benchmarked on Connectome in this cycle. The recommendations are ranked experiments supported by model provenance, task fit, local evidence and computational reasoning; they are not forecasts of a particular future WP.
